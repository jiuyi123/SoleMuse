# AI 创意多模态全球时尚鞋履提示词平台产品需求文档（PRD）V1.0

| 项目 | 内容 |
| --- | --- |
| 产品暂定名 | AI 创意多模态全球时尚鞋履提示词平台 |
| 文档版本 | V1.0 |
| 目标用户 | 鞋履及相关品类设计师、作品浏览者 |
| 产品阶段 | 首期需求 |

## 1. 项目概述

### 1.1 项目建设背景

随着 AI 生成技术逐步进入鞋履设计创作环节，设计师对灵感参考、作品展示、同行交流及创作素材复用的需求持续提升。但优质鞋履设计作品、AI 生成提示词（Prompt）和设计经验仍分散于不同渠道，存在作品来源不清、检索效率低、知识难以沉淀与复用等问题。

本项目拟建设面向鞋履时尚产业的 AI 创意设计平台，汇聚设计师、鞋企及相关产业参与者的优质内容，逐步沉淀鞋款设计作品、Prompt 与创作经验等多模态设计资产，并为 AI 数据知识产权保护与应用探索提供业务载体。

项目将以 AI 技术赋能鞋履设计创新为核心，形成覆盖设计内容汇聚、知识资产沉淀、设计师协作交流与创意应用支撑的能力体系。通过将分散的设计资源转化为可检索、可理解、可复用的数字化资产，平台有望提升鞋履创意资源的流通效率，为设计师与鞋企持续提供创意灵感、设计参考与创新支撑。


### 1.2 产品定位

面向鞋履及相关品类设计师的作品展示与创意交流平台。平台以设计作品为内容核心，提供发布、发现与作品级互动能力；通过统一的 AI 生成源标签，增强作品的来源透明度和可检索性。

## 2. 一期建设范围

### 2.1 一期目标

一期以微信小程序为主要用户入口，建设面向设计师的产品最小可行版本（MVP），沉淀用户、作品及互动数据。首期聚焦验证设计内容汇聚、内容浏览与社区交流的基础闭环，为后续能力扩展积累真实的用户与内容资产；产品需具备服务千级用户规模的基础能力。

一期目标如下：

1. 建立内容汇聚能力：支持设计师上传、编辑、发布和管理作品，规范沉淀作品展示图片、提示词（Prompt）、AI 生成源模型/工具、作品标题、分类、风格标签、创作说明及发布时间等基础数据；其中展示图片、Prompt 和生成源模型/工具为作品内容资产的核心字段。
2. 建立内容浏览能力：支持用户浏览、搜索、筛选和收藏作品，提高设计内容的发现效率。
3. 建立社区互动能力：围绕单个作品提供点赞与独立评论区，促进设计师之间的观点交流与创作反馈。
4. 建立用户账户与个人中心能力：支持用户注册、登录及个人资料维护，并提供“我的作品、我的收藏、我的点赞、我的评论”等个人内容与行为记录查看能力，帮助用户管理个人信息及平台内资产。

### 2.2 本期实现内容

- 微信小程序端：提供首页、榜单、创作、消息、我的五个一级板块，以及登录注册、搜索、作品详情等基础页面与功能入口。
- 作品管理：支持设计师上传、编辑、发布、下架及查看自己的作品；沉淀展示图片、Prompt、生成源模型/工具、标题、分类、标签和创作说明等信息。
- 作品浏览与互动：支持公开作品浏览、关键词搜索、规则筛选、点赞、收藏及作品独立评论区。
- 用户信息管理：支持用户资料维护，以及我的作品、收藏、点赞、评论查看。
- 消息通知：支持展示与用户相关的互动消息、作品状态消息及系统通知。
- AI 来源标识：支持创作者填写生成源模型/工具，并在作品列表及详情页以统一标签展示。

### 2.3 本期不实现内容

- 一期仅提供微信小程序端，不建设 Web、App 或企业管理端；项目不按企业级备案方案实施，具体备案义务由相关责任方根据实际业务与监管要求确认。
- 不提供在线 AI 生成、作品内容自动识别/分类/打标及个性化推荐算法；作品分类、标签和生成源信息由创作者填写，内容按最新发布或明确规则展示。
- 不提供在线编辑协作、作品下载与交易、版权确权及私信群聊等扩展能力。

## 3. 用户分析

### 3.1 角色与权限

| 角色 | 核心权限 |
| --- | --- |
| 游客 | 浏览公开作品与搜索结果；不可上传、点赞、评论、收藏。 |
| 注册用户 | 登录后浏览；点赞、评论、收藏；维护个人资料。 |
| 设计师 | 一期中，完成注册并发布作品的用户即视为设计师；具备注册用户权限，并可上传、编辑、发布、下架自己的作品。 |

说明：一期不设置设计师认证、人工审核或额外发布门槛，所有完成注册的用户均可进入“创作”发布作品。

### 3.2 核心用户场景

| 场景 | 用户故事 | 用户价值 |
| --- | --- | --- |
| 发布作品 | 作为设计师，我希望上传作品并填写模型来源、标签和简介，从而让同行理解和发现我的创作。 | 获得展示与交流机会。 |
| 查找灵感 | 作为浏览者，我希望搜索并筛选作品，从而快速找到目标风格、品类或模型来源的参考。 | 降低找素材成本。 |
| 围绕作品交流 | 作为设计师，我希望在单个作品下评论和回复，从而获得反馈或讨论设计思路。 | 形成专业社区互动。 |

## 4. 主要页面与使用方式

### 4.1 板块级设计

平台采用底部五栏导航，用户可在首页、榜单、创作、消息和我的之间切换。

| 板块 | 板块定位 | 核心职责 |
| --- | --- | --- |
| 首页 | 内容发现与浏览 | 提供最新作品、热门标签和搜索入口，承接用户进入作品详情后的浏览与互动。 |
| 榜单 | 热门内容聚合 | 按公开、预先定义的热度规则展示热门作品排行；不使用个性化推荐算法。 |
| 创作（“+”） | 作品创作与发布 | 为登录设计师提供作品填写、保存草稿与发布入口。 |
| 消息 | 互动与系统通知 | 汇总与本人相关的点赞、评论、作品状态及系统通知。 |
| 我的 | 个人信息与内容管理 | 提供个人资料维护，以及个人作品、收藏、点赞和评论的查看与管理。 |

### 4.2 页面级设计

| 所属板块 | 页面 | 页面主要内容 |
| --- | --- | --- |
| 首页 | 首页 | 最新发布作品、热门标签、搜索入口。 |
| 首页 | 搜索结果页 | 搜索框、筛选条件、排序、作品结果列表及无结果状态。 |
| 首页/榜单 | 作品详情页 | 展示图片、Prompt、生成源标签、作品说明、作者信息、点赞、收藏和评论区。 |
| 榜单 | 榜单页 | 热门作品排行及排行规则说明入口。 |
| 创作 | 发布作品页 | 展示图片上传、标题、Prompt、生成源模型/工具、分类、标签、创作说明等字段，提供草稿与发布操作。 |
| 创作 | 编辑作品页 | 展示已保存作品信息，支持编辑、重新发布或下架操作。 |
| 消息 | 消息列表页 | 按时间展示点赞、评论、作品状态和系统通知；点击后进入关联内容或通知详情。 |
| 我的 | 个人主页/资料页 | 头像、昵称、职业/角色、擅长品类等个人资料的查看与编辑。 |
| 我的 | 我的内容页 | 我的作品、我的收藏、我的点赞、我的评论等内容与行为记录。 |

### 4.3 使用方式

1. **浏览与搜索**：用户进入首页后，可浏览最新发布的作品，也可通过热门标签或搜索框查找内容。搜索结果页支持按分类、风格标签、生成源模型/工具及发布时间进行筛选和排序；用户点击作品卡片进入作品详情页查看图片、Prompt、生成源及创作说明。
2. **查看榜单**：用户进入榜单页后，可查看按公开热度规则生成的热门作品排行；点击榜单作品可进入对应作品详情页。榜单仅展示平台统一计算的结果，不随个人用户而变化。
3. **登录与身份切换**：未登录用户可浏览公开作品、搜索结果与榜单。当用户点击点赞、收藏、评论、创作、消息或“我的”中的个人内容时，系统应引导其注册或登录；登录成功后返回原操作页面或继续完成原操作。
4. **创作与发布**：设计师点击底部“创作（+）”进入发布作品页，上传展示图片并填写标题、Prompt、生成源模型/工具、分类、标签及创作说明等信息。用户可先保存草稿，或在满足必填校验后发布；发布成功后可跳转至作品详情页或在“我的作品”中查看。
5. **作品互动**：用户在作品详情页可点赞、收藏和发表评论。点赞、收藏可再次点击取消；评论发布后展示在该作品的独立评论区，用户可删除自己的评论，并可对其他评论进行单层回复。
6. **消息查看**：当作品获得点赞、评论或作品状态发生变化时，系统在消息页汇总相关通知。用户点击消息后可跳转至对应作品详情、评论位置或通知详情；系统通知用于展示平台公告及必要的操作提醒。
7. **个人内容管理**：用户进入“我的”后，可维护头像、昵称等个人资料，并分别查看我的作品、我的收藏、我的点赞和我的评论。设计师可在“我的作品”中编辑、发布或下架本人作品；其他个人列表支持进入对应作品或评论内容查看。

## 5. 详细功能需求

### 5.1 用户账户与“我的”

| 编号 | 需求 |
| --- | --- |
| R-01 | 系统应在微信小程序端提供注册、登录与退出登录能力；具体采用微信授权、手机号验证或其组合方式，由接入方案确定。 |
| R-02 | 系统应在注册或首次完善资料时收集昵称、头像、所在地区、职业/角色、擅长品类等字段；必填字段及隐私告知文案待确认。 |
| R-03 | 系统应允许用户在个人中心查看和修改本人可编辑资料。 |
| R-04 | 系统应在“我的”板块展示“我的作品、我的收藏、我的点赞、我的评论”，各列表应可进入关联作品或评论内容。 |

### 5.2 创作与作品管理

| 编号 | 需求 |
| --- | --- |
| R-05 | 所有完成注册的用户均应能上传图片作品；系统应校验文件类型、单文件大小、图片数量和分辨率，具体阈值待确认。 |
| R-06 | 发布作品时，系统应要求填写作品标题、展示图片、提示词（Prompt）、AI 生成源模型/工具和作品分类；风格标签、创作说明、模型版本、工作流和二次编辑说明为可选字段。 |
| R-07 | 系统应支持一件作品包含封面图和多张详情图；作品详情页应按上传顺序展示。 |
| R-08 | 设计师应能保存草稿、编辑未下架作品以及下架自己的作品。 |
| R-09 | 系统应在发布成功后生成公开可访问的作品详情页，并显示展示图片、Prompt、作者、发布时间、分类、标签、生成源及互动数据。 |
| R-10 | 系统应阻止未登录用户上传，且不得允许用户编辑、删除或下架他人的作品。 |

### 5.3 生成源信息与标签

| 编号 | 需求 |
| --- | --- |
| R-11 | 系统应提供由创作者填写的 AI 生成源字段，并为每件作品保存至少“生成模型/工具名称”；模型版本、工作流和二次编辑说明为可选字段。一期不校验或自动识别该字段真实性，平台自动检测能力列入后续评估。 |
| R-12 | 系统应提供预置的模型/工具标签库，供创作者在发布作品时选择。 |
| R-13 | 作品列表卡片和作品详情页应展示生成源标签；未使用 AI 或来源不明时，应展示“非 AI 生成”或“来源未标注”等规范标签。 |
| R-14 | 系统应允许用户通过生成源标签筛选作品。 |
| R-15 | 系统应保留创作者提交的生成源信息及其后续修改记录，用于作品信息追溯。 |

### 5.4 首页、作品浏览与搜索

| 编号 | 需求 |
| --- | --- |
| R-16 | 系统应在首页展示最新发布作品、热门标签及搜索入口；首页内容不基于个人用户画像生成。 |
| R-17 | 系统应提供作品广场和搜索结果页，以卡片流展示公开作品；每张卡片至少展示封面、标题、作者、生成源标签及点赞/收藏/评论数据。 |
| R-18 | 系统应支持按关键词搜索作品标题、描述、标签和作者昵称。 |
| R-19 | 系统应支持按作品分类、风格标签、AI 生成源及发布时间筛选；排序至少支持最新发布和热度排序。系统应在榜单页按预先定义的公开热度规则展示热门作品排行，且不得基于用户个人画像生成。 |
| R-20 | 系统应在搜索无结果时展示空状态，并提供清除筛选或返回作品广场的入口。 |

### 5.5 榜单、互动与消息

| 编号 | 需求 |
| --- | --- |
| R-21 | 登录用户应能对公开作品点赞或取消点赞；同一用户对同一作品仅可保留一次点赞。 |
| R-22 | 登录用户应能收藏或取消收藏公开作品；收藏内容应在“我的收藏”中展示。 |
| R-23 | 每件作品应有独立评论区，登录用户应能发布文字评论、查看评论列表并删除自己的评论。 |
| R-24 | 系统应支持对评论进行单层回复，回复应显示被回复对象及发布时间；是否支持多层嵌套回复，本期默认不支持。 |
| R-25 | 对已下架的作品，系统应停止新增点赞、收藏和评论。 |
| R-26 | 系统应在消息页按时间汇总用户收到的点赞、评论、作品状态和系统通知；用户点击消息后应能进入关联内容或查看通知详情。 |

## 6. 验收标准

一期验收以“核心功能可用、主流程完整、页面体验基本稳定”为原则。具体测试用例、性能指标和验收样本可在设计与开发阶段进一步明确。

1. 用户能够正常进入首页、榜单、创作、消息和我的五个一级板块，页面跳转及基础展示符合第四章描述。
2. 用户能够完成注册登录、个人资料维护，以及个人作品、收藏、点赞和评论等内容的查看。
3. 设计师能够完成作品信息填写、草稿保存、发布、查看、编辑和下架等基本操作；发布后的作品信息可在前台正常展示。
4. 用户能够浏览作品、使用搜索与筛选查找内容、查看榜单，并在作品详情页查看展示图片、Prompt、生成源及相关说明。
5. 用户登录后能够完成点赞、收藏、评论等互动操作，并可在消息页查看与本人相关的互动或状态通知。
6. 对常见的未登录、必填信息缺失、搜索无结果及内容已下架等情况，系统应提供清晰提示，不出现阻断性页面错误。
7. 在预期用户规模下，主要页面与核心操作应保持基本可访问和可用；具体响应时间、并发量及稳定性目标待后续确认。

## 7. 非功能性要求

### 7.1 终端与兼容性

- 一期仅面向微信小程序提供服务，应适配主流微信小程序运行环境及常见移动设备。
- 不建设 Web、原生 App 或企业管理端；如后续新增端侧，应另行评估功能一致性与数据同步方案。

### 7.2 性能与可用性

- 产品应满足千级用户规模下的基础访问需要，首页、榜单、创作、消息、我的及作品详情等核心页面应能够正常打开和使用。
- 图片上传、作品发布、搜索、互动等核心操作应提供进行中、成功或失败反馈；网络异常或服务异常时，系统应提示用户重试，避免出现无响应或阻断性错误页面。
- 具体页面响应时间、并发量、图片存储容量和可用性目标待后续技术评估确认。

### 7.3 数据与安全

- 系统应确保用户只能查看和修改本人有权限访问的个人资料、作品和互动内容，不得访问或修改其他用户的私有信息。
- 用户注册资料、作品信息、Prompt、生成源信息及互动数据应在传输和存储过程中获得基础安全保护；具体技术措施由技术方案确定。
- 用户资料收集、使用与展示应符合适用的隐私保护及相关监管要求，具体告知与授权内容待相关责任方确认。
